cw audit ENV: output preview (#6189). Target, not shipped.

SPEC.md "Sandbox audit log" defines this command, and `cw --cloud policy
log` and `cw info`'s refusal line at the end; the journey is
docs/journeys/audit-log.md. This file is the exact text they print, for
one example Sandbox, before any code exists. The dashboard's Audit log
page shows the same events in the same words.

The example: the Sandbox walk-docs, created yesterday by ana@example.com,
selects the organization policy walk-docs. Revision 1 allows docs.rs:443.
Revision 2 also allows crates.io:443. The local time zone is UTC. At a
terminal the day headings are bold and the counts and times are dim; piped,
the text is the same with no escape sequences.

Each line is the local time the event began, its kind, and one sentence.
Events are newest first, by when they began. A line too long for the
terminal wraps under its sentence, after a `·` where it can, else at a word.

→ cw --cloud policy allow walk-docs pypi.org:443

Notes:
- The `→` step names the newest refused event a rule can allow under the
  selected policy. crates.io:443 reads "Allowed since rev 2", so it gets no
  step; 8.8.8.8:53 is UDP, which no rule carries; the withheld name has no
  text to allow.
- lee@example.com is an admin. The member ana@example.com, every other
  admin and every owner see this same line, client IP included.
- Exec and preview sessions fold per actor, client IP and hour; terminal,
  SSH and desktop sessions are one line each.
- walk-docs was created yesterday, so nothing is older than the range and
  the `--since 90d` hint is left out.

`cw audit` words a timeout the same way, with "events" for "refusals". It
reads ungrouped, so the rate limit is not its; `cw info` leaves its
`Refused:` line out after either.
