Cloud

zsh · ~/my-appIdle

cw create --name my-app --image workspace prints: my-app, cloud VM, 2 vCPU, 8 GiB RAM, 10 GiB disk. cw run claude --in my-app prints: Started Claude Code in my-app/claude, cloud.

On your own Linux machine or Apple Silicon Mac, each sandbox is a VM isolated by Cloud Hypervisor or Virtualization.framework, with no account needed. In the cloud, it is a hosted VM billed per second. The commands are the same at either end.

    (4.0)

    Isolation

    Choose your isolation.

    Every sandbox is its own VM with its own guest kernel, inside a hypervisor boundary. When source code, credentials or customer data need more, the hardware can encrypt the sandbox's memory while it runs.

    4.1Hardware

    CPU, memory and disk. Confidential sandboxes* run on AMD SEV-SNP processors.

    4.2Host kernel

    Your machine, or ours. It runs the hypervisor and stays outside every sandbox.

    4.3Hypervisor

    Cloud Hypervisor on Linux, Virtualization.framework on macOS. One VM per sandbox.

    4.4Guest kernel

    One per sandbox. Never shared with the host or another sandbox.

    4.5Session

    The agent and your code. auth · codex · 8 GB

    4.6Encrypted memory

    Each sandbox's memory is encrypted with its own key. The host kernel and hypervisor only see ciphertext, and cw report auth verifies it with the processor's attestation.

    *In private alpha, access available upon request.
