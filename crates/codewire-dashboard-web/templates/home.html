(0.3)

Safety

Choose what your
agent can access.

Codewire VMs give you control over what your agent can reach. Use network policies to choose which hosts and ports it can connect to. The credential proxy adds the credentials those services need to outgoing requests, keeping the underlying keys outside the sandbox.

Your agent

Credential proxy

Keep your API key outside the VM.

Your agent sends a stand-in credential. The proxy substitutes your API key before forwarding the request.

Network egress control

Choose where your sandbox can connect.

Set the destinations your agent can reach. Codewire checks the hostname and port before connecting.

Illustrations: a managed API-key request and a custom network policy on a local VM. For a hosted sandbox, cw info NAME shows its policy and enforcement status. Personal sign-ins and application secrets have different delivery rules.

Local + cloud

Choose where your sandbox runs.

Local

cw create --local --name my-app --path . prints: Environment my-app created, local VM, 2 vCPU, 4 GiB RAM, 20 GiB disk. cw run claude --in my-app prints: Started Claude Code in my-app/claude, local VM.

Cloud

zsh · ~/my-appIdle

cw create --name my-app --image workspace prints: my-app, cloud VM, 2 vCPU, 8 GiB RAM, 10 GiB disk. cw run claude --in my-app prints: Started Claude Code in my-app/claude, cloud.

On your own Linux machine or Apple Silicon Mac, each sandbox is a VM isolated by Cloud Hypervisor or Virtualization.framework, with no account needed. In the cloud, it is a hosted VM billed per second. The commands are the same at either end.

Agent-to-agent messaging.

Agents in separate sandboxes send messages to each other through Codewire’s built-in mesh relay. One agent can ask another to review a change, and the reviewer can reply with its findings.

    (4.0)

    Isolation

    Choose your isolation.

    Every sandbox is its own VM with its own guest kernel, inside a hypervisor boundary. When source code, credentials or customer data need more, the hardware can encrypt the sandbox's memory while it runs.

    4.1Hardware

    CPU, memory and disk. Confidential sandboxes* run on AMD SEV-SNP processors.

    4.2Host kernel

    Your machine, or ours. It runs the hypervisor and stays outside every sandbox.

    4.3Hypervisor

    Cloud Hypervisor on Linux, Virtualization.framework on macOS. One VM per sandbox.

    4.4Guest kernel

    One per sandbox. Never shared with the host or another sandbox.

    4.5Session

    The agent and your code. auth · codex · 8 GB

    4.6Encrypted memory

    Each sandbox's memory is encrypted with its own key. The host kernel and hypervisor only see ciphertext, and cw report auth verifies it with the processor's attestation.

    *In private alpha, access available upon request.
